# AI agent security
## When it applies
Any system where an LLM or coding agent (Claude Code, Codex) reads text from chat, email, issues, calendar invites, web pages or webhooks and can then run tools, change files, call APIs or send messages. Applies in full to the chat bots: jobs arrive from Slack, GitHub, Linear, Gmail, Calendar or webhooks, the agent runs on the owner's machine with the owner's credentials, and untrusted people can write in the same threads. For signature checks, OAuth and secret storage, see `web-security.md`.
## Standards
- **OWASP Top 10 for LLM Applications 2025 (index)**: Use LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM05 Improper Output Handling, LLM06 Excessive Agency, LLM07 System Prompt Leakage and LLM10 Unbounded Consumption as the checklist for the spec's threat list. Why: it is the community-reviewed baseline, and these six hit a chat-driven coding agent directly. Source: https://genai.owasp.org/llm-top-10/
- **LLM01 Prompt injection**: Treat every word from chat, email, issues, PR comments, files and web pages as untrusted data that can carry instructions; do not rely on "ignore injected instructions" in the system prompt; separate trusted instructions from untrusted content, and limit what a hijacked agent could do (the real control). Why: no filter catches all injections, so assume one will succeed and bound the damage. Source: https://genai.owasp.org/llmrisk/llm01-prompt-injection/
- **Prompt Injection Prevention Cheat Sheet**: Mark and isolate untrusted content, validate model output before acting on it, and watch for indirect injection through documents and tool results. Why: gives concrete patterns to apply in the bot's prompt and tool layer. Source: https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html
- **LLM06 Excessive agency**: Give the agent only the tools, permissions and autonomy the job needs (minimal tool set, narrow scopes, no open-ended shell or "run anything" unless sandboxed), and require approval for high-impact actions. Why: damage comes from what the agent is allowed to do when its output is wrong or manipulated. Source: https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
- **LLM02 Sensitive information disclosure**: Keep secrets, private files and other users' data out of the model's context unless the task needs them; scrub tool output and logs; do not let a reply in a shared thread include private data from another source. Why: the agent can read the owner's disk and mail, and a thread may include people who must not see it. Source: https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/
- **LLM05 Improper output handling**: Treat model output as untrusted input to the next system: never pass it unchecked to a shell, SQL, URL fetcher, or a renderer that fetches links or images. Why: injected text can turn into commands or into data leaving through a rendered link. Source: https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/
- **OWASP Top 10 for Agentic Applications (2026)**: Use it alongside the LLM list for agent-specific risks (goal hijack, tool misuse, identity and privilege abuse, and others) and apply its "least agency" idea: autonomy bounded by the task. Why: it covers multi-step agents with tools and inherited credentials, which the LLM list only touches. Source: https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/
- **OWASP AI Agent Security Cheat Sheet**: Follow its sections: tool security and least privilege, input validation and injection defense, memory and context security, human-in-the-loop controls, output validation, monitoring, multi-agent security, data protection; fail closed on unknown tools or missing approval rules. Why: the most practical OWASP checklist for building an agent. Source: https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html
- **Human approval for destructive and outward actions**: Require an explicit approval from the verified owner for deleting or overwriting data, force-push or history rewrite, merges and deploys, sending email or messages to new recipients, spending money, changing permissions, and anything touching secrets; show the exact action in the approval and bind the approval to that action only, expiring it soon. Why: the agent proposes, a person authorizes; one approval must not stretch to later actions. Source: https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html
- **Requester identity decided by the platform, not the model**: Take the requester from the signed event (Slack user id, GitHub login, Linear user id, Gmail sender after authentication checks), never from text in the message or from the model's reading of it; map that id to roles in code. Why: anyone in a thread can write "I am the owner"; only the platform's verified field is real. Source: https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html
- **Allowlists**: Allowlist who can start jobs (user ids, channels, repos, workspaces), which tools and commands the agent may run, which paths it can write, and which hosts it may reach; default deny; messages from non-allowlisted people are ignored or get a fixed refusal and never reach the agent. Why: untrusted people share the same threads; allow by identity, not by trust in content. Source: https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
- **Tool credential isolation**: Keep tokens in the bot or a broker process; the agent calls a tool that injects the credential and never receives the raw token in its context, environment or files; use short-lived, narrowly scoped tokens per job, and run the agent in a sandbox or separate OS account without access to the owner's other secrets. Why: what the model can read, an injection can leak. Source: https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html
- **Output exfiltration (links, images, markdown)**: Strip or neutralize auto-fetching content in replies (markdown images, HTML tags, links to attacker-chosen hosts, long encoded URLs), allow only links to an approved host list, and do not auto-unfurl links in replies. Why: a hijacked agent can leak data by writing an image or link whose URL carries the secret. Source: https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html
- **Audit logs**: Log for every job the verified requester id, source message id, tools called with arguments (secrets redacted), approvals given and by whom, files and external systems changed, result and cost; keep logs append-only and out of the agent's write reach. Why: you need to answer who asked for what and what the agent did, and an agent must not edit its own trail. Source: https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html
- **Limits and kill switch**: Cap time, tokens, spend, tool calls, concurrency and files changed per job; provide one owner-only command or flag file that stops all running jobs, revokes tool tokens and pauses intake. Why: a runaway or hijacked job must be stoppable in seconds (LLM10 Unbounded Consumption). Source: https://genai.owasp.org/llmrisk/llm102025-unbounded-consumption/
- **Memory and context hygiene**: Do not carry untrusted thread content into long-term memory or system instructions; scope context per thread and per requester. Why: poisoned memory turns one injection into a lasting one. Source: https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html
